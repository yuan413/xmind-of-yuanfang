# Wiki Schema — 深入研究

## 页面类型

| 类型 | 目录 | 目的 |
| --- | --- | --- |
| 实体 | wiki/entities/ | 命名事物（人物、工具、组织、数据集） |
| 概念 | wiki/concepts/ | 思想、技术、现象、框架 |
| source | wiki/sources/ | 论文、文章、演讲、书籍、博客文章 |
| 查询 | wiki/queries/ | 正在调查中的开放问题 |
| 比较 | wiki/comparisons/ | 并排分析相关实体 |
| 综合 | wiki/synthesis/ | 跨领域总结和结论 |
| 概述 | wiki/ | 高级项目摘要（每个项目一个） |
| 论文 | wiki/thesis/ | 工作假设及其随时间演变 |
| 方法论 | wiki/methodology/ | 研究方法、协议和研究设计 |
| 发现 | wiki/findings/ | 个体实证结果或观察 |

## 命名规范

*   文件：`kebab-case.md`
*   实体：尽可能匹配官方名称（例如：`openai.md`、`gpt-4.md`）
*   概念：描述性名词短语（例如：`chain-of-thought.md`
*   来源：`author-year-slug.md`（例如，`wei-2022-cot.md`）
*   查询：问题作为 slug（例如，`does-scale-improve-reasoning.md`）
*   论题：假设作为 slug（例如，`scaling-improves-reasoning.md`）
*   方法论：方法名称（例如，`systematic-review.md`，`ablation-study.md`)
*   发现：描述性别名（例如，`larger-models-better-few-shot.md`）

## 前文

所有页面都必须包含 YAML 前文：

```yaml
---
类型：实体 | 概念 | 来源 | 查询 | 比较 | 综合 | 概述
标题：人类可读的标题
标签：[]
相关：[]
创建：YYYY-MM-DD
更新：YYYY-MM-DD
---
```

源页面还包括：

```yaml
作者: []
年份: YYYY
网址: ""
会议/期刊名称: ""
```

论文页面还包括：

```yaml
置信度：低 | 中 | 高
状态：推测性 | 支持 | 反驳 | 已解决
```

发现页面还包括：

```yaml
来源: "[[source-slug]]"
置信度: 低 | 中 | 高
复制: 真 | 假 | 空
```

## 索引格式

`wiki/index.md` 列出了按类型分组的所有页面。每个条目：

```
- [[页面缩写]] — 一行描述
```

## 日志格式

`wiki/log.md` 按倒序时间记录活动：

```
## YYYY-MM-DD

- 已采取行动/已记录发现
```

## 交叉引用规则

*   使用 `[[页面缩写]]` 语法在维基页面之间建立链接
*   每个实体和概念都应该出现在 `wiki/index.md 中`
*   查询链接到它们所依据的来源和概念
*   综合页面通过 `related: 引用所有贡献来源`
*   研究结果通过 `source:` 前置字段链接回其来源
*   论文页面通过 `related: 引用支持性和反驳性发现`
*   方法页面被使用它们的发现所引用

## 矛盾处理

当来源相互矛盾时：

1.  注意相关概念或实体页面中的矛盾之处
2.  创建或更新一个查询页面来跟踪未解决的问题
3.  从查询页面链接两个来源
4.  在积累足够证据后，在综合页面中解决

## 研究特定惯例

*   随着证据的积累，及时更新论文页面——它们是活文档
*   每个发现都应在已知时评估可复制性状态
*   方法页面解释的是*为什么* （理由），而不仅仅是*怎么做*
*   区分直接证据和推论在查找页面
